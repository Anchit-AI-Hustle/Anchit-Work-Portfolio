# Sarvam AI — getting started, and the honest answer on cloning

## The headline: Sarvam cannot speak in your cloned voice

Sarvam's public REST API has **no voice-cloning surface**. Verified against
Sarvam's own OpenAPI-generated SDKs — `sarvamai@1.1.7` (JS) and `sarvamai 0.1.28`
(Python), both generated by Fern from Sarvam's spec:

| Check | Result |
| --- | --- |
| Any `clone` / `voice` / `voice_id` endpoint in either SDK | **None.** Resources are: text, speechToText, textToSpeech, pronunciationDictionary, chat, documentIntelligence, + job/streaming variants |
| `speaker` parameter type | **Closed enum of 44 stock voices** (37 on `bulbul:v3`, 7 on `bulbul:v2`) |
| Any field accepting a custom/cloned voice id | **None.** The full request is `text`, `target_language_code`, `speaker`, `pitch`, `pace`, `loudness`, `speech_sample_rate`, `enable_preprocessing`, `model`, `output_audio_codec`, `temperature`, `dict_id`, `enable_cached_responses` |

Sarvam's voice cloning is a **Sarvam Studio** feature — it records ~10 seconds in
the browser and makes the persona reusable *inside Studio* (its TTS and Dubbing
UI). That is why the cloning docs live under `docs.sarvam.ai/creative-*`
(the Studio product) and not under `docs.sarvam.ai/api-reference-docs/*`.

**Consequence for this repo:** Sarvam can never be the provider that speaks as
you. It is the Indic / code-mixed / always-works voice. Your cloned voice comes
from ElevenLabs, Cartesia, Fish, a Hugging Face fine-tune, or self-hosted XTTS.

> If Sarvam ships cloned-voice ids later, this is a one-variable change: set
> `SARVAM_VOICE=<the id>`. `api/tts.js` sends any unrecognised speaker as-is and
> retries once with the model default, so trying it can't break narration.

## What changed in `api/tts.js`

Two live defects, both fixed:

1. **A female stock voice was narrating your first-person copy.** The Sarvam
   default was `speaker: 'anushka'` — a female voice reading "I'm building…".
   Now defaults to `shubh` (male, and Sarvam's own `bulbul:v3` default).
2. **A stock voice could pre-empt your real clone.** Sarvam ran 4th, *ahead of*
   Hugging Face and self-hosted XTTS — both of which serve your actual voice. So
   with only `SARVAM_API_KEY` and `XTTS_API_URL` set, the site chose the stranger.
   Sarvam now runs **last**.

Also modernized: `bulbul:v2` → `bulbul:v3`, correct per-model character limits
(2500 on v3 vs 1500 on v2), model-appropriate parameters (`temperature` on v3,
`enable_preprocessing` on v2 — v3 rejects `pitch`/`loudness`), speaker/model
compatibility guarding, and `output_audio_codec` support.

Cascade order is now clone-capable first:

```
elevenlabs → cartesia → fish → huggingface → xtts → sarvam (stock)
```

## Getting started

1. Get a key at <https://dashboard.sarvam.ai/>.
2. Verify it and see all three APIs work:

   ```bash
   SARVAM_API_KEY=sk_... npm run sarvam:check
   ```

   That synthesizes with the **exact body `api/tts.js` sends** — it imports the
   same `sarvamConfig()` resolver, so it cannot drift from production — then
   transcribes your own `audio/anchit-xtts-sample.wav` and runs a translation.
   It writes `audio/sarvam-test.wav`; play it.

   Audition voices without touching your deployed config:

   ```bash
   npm run sarvam:check -- --speaker ritu --lang hi-IN
   npm run sarvam:check -- --model bulbul:v2
   ```

3. Deploy the key: `scripts/setup-env.sh`, or `npx vercel env add SARVAM_API_KEY`.

4. Confirm what the live site is doing:

   ```bash
   curl -s https://anchit-tandon.com/api/tts | jq
   # want: "clonedVoiceReady": true
   ```

   Every audio response also carries `X-Voice-Provider` and `X-Voice-Clone`, so
   you can tell at a glance whether a given clip was actually you.

## Environment variables

Everything except the key is optional. **An invalid value falls back to a working
default rather than failing the call** — an out-of-range number would come back
as a 400, which the cascade would read as "provider down" and silently skip.
Check what actually resolved with `curl -s .../api/tts | jq .sarvam`.

| Variable | Default | Notes |
| --- | --- | --- |
| `SARVAM_API_KEY` | — | Required; without it Sarvam is skipped entirely |
| `SARVAM_MODEL` | `bulbul:v3` | or `bulbul:v2` (legacy) |
| `SARVAM_VOICE` | `shubh` (v3) / `abhilash` (v2) | Must match the model — v2 and v3 speakers are not interchangeable. Lowercase and case-sensitive |
| `SARVAM_LANG` | `en-IN` | `hi-IN`, `bn-IN`, `gu-IN`, `kn-IN`, `ml-IN`, `mr-IN`, `od-IN`, `pa-IN`, `ta-IN`, `te-IN` — Odia is `od-IN`, not `or-IN` |
| `SARVAM_CODEC` | `wav` | `mp3`, `opus`, `flac`, `aac`, `linear16`, `mulaw`, `alaw` — `mp3` is far smaller over the wire |
| `SARVAM_PACE` | `1.0` | v3: 0.5–2.0 · v2: 0.3–3.0 |
| `SARVAM_TEMPERATURE` | `0.6` | v3 only, 0.01–2.0. Higher = more expressive, more artefacts |
| `SARVAM_SAMPLE_RATE` | `24000` | 8000/16000/22050/24000; 32000/44100/48000 are v3-only |

`SARVAM_VOICE` is the one value that is *not* silently corrected: an unknown
speaker is sent as-is, then retried once with the model default. That way a
future cloned-voice id gets a real attempt instead of being discarded.

## API contract (verified against the SDKs)

Base URL `https://api.sarvam.ai` · auth header `api-subscription-key: <key>`

**`POST /text-to-speech`** → `{ request_id, audios: [base64] }`

- `bulbul:v3` — 2500 chars, `pace` 0.5–2.0, `temperature` 0.01–2.0 (default 0.6),
  preprocessing automatic, **no** `pitch`/`loudness`, default 24 kHz
- `bulbul:v2` — 1500 chars, `pitch`/`loudness` supported, `pace` 0.3–3.0
- Speakers are **lowercase and case-sensitive**; a v3 name on v2 is a `400`
- Sample rates 8000/16000/22050/24000; 32000/44100/48000 are v3 REST-only

**`POST /speech-to-text`** (multipart) → `{ transcript, language_code, language_probability }`

- `saarika:v2.5` (default) transcribes in the spoken language; `saaras:v3` adds
  `mode`: `transcribe` | `translate` | `verbatim` | `translit` | `codemix`
- `language_code: unknown` auto-detects
- **Sync endpoint is for clips under 30s** — use the Batch API for longer audio.
  Your sample is 30.7s, so `sarvam-check.mjs` trims it to 20s first.

**`POST /translate`** → `{ translated_text, source_language_code }`

- `mayura:v1` (1000 chars) or `sarvam-translate:v1` (2000 chars)

## Getting your actual voice on the site

```bash
node scripts/elevenlabs-clone.mjs     # clones audio/anchit-xtts-sample.wav → voice_id
npm run tts:serve                     # self-hosted XTTS, free forever
```

If you specifically want Sarvam's clone quality, it's a manual Studio export
today: clone in Studio, generate the audio there, download it. There is no way
to drive it from this codebase.
