# Project SkillTree & Guide Library

The portfolio now applies a second shared layer beneath the App Skill Map: every application capability becomes a project path, and every project receives an original, reusable guide pack.

The design combines two useful product patterns without cloning either source:

1. **Visual skill-tree navigation** — ordered project nodes, prerequisites, progress states, current-app context and direct navigation.
2. **Curated guide and prompt discovery** — searchable categories, model and type filters, copy-ready templates, customization fields, saved guides and a prompt generator.

No third-party prompts, gated content, tracking code, reference-page tokens or access credentials are stored in the repository or build output.

## Product contract

Every generated HTML application receives:

- a persistent **Project Playbooks** launcher;
- a project tree scoped to the current app by default;
- an all-app view covering every first-party and registered external application;
- one project node for every app capability;
- ordered dependencies between project stages;
- Available → In progress → Completed project states;
- four original playbooks per project;
- a searchable guide library;
- saved guides and local copy history;
- a context-aware prompt customizer;
- a structured prompt builder;
- direct navigation back into the relevant app.

The four automatically generated playbooks are:

1. **Quickstart Guide** — outcome, prerequisites, execution path, failure modes and completion checklist.
2. **Operator Mega-Prompt** — role, context, task, constraints and output format.
3. **Evidence Audit Prompt** — independent recomputation, PASS/FAIL checks, anomalies and remediation.
4. **9.5/10 Improvement Loop** — transparent scoring, revision, re-scoring and change log without score inflation.

Because the catalog is generated from the App Skill Map, every current capability becomes a project automatically. A future app receives project nodes and guide packs as soon as it is registered in `assets/app-skill-map.js`.

## Architecture

```text
assets/app-skill-map.js
  └─ canonical app, department and capability registry

assets/project-playbooks.js
  ├─ reads the App Skill Map at runtime
  ├─ converts every capability into a project node
  ├─ creates ordered project dependencies
  ├─ generates four guide packs per project
  ├─ detects the current route or external host
  ├─ stores project state, saved guides and context locally
  ├─ builds customized prompts
  └─ exposes window.AnchitProjectPlaybooks

assets/project-playbooks.css
  ├─ isolated ppb-* component styles
  ├─ project chain and guide-card layouts
  ├─ prompt builder and customizer drawer
  ├─ responsive and keyboard-accessible controls
  └─ reduced-motion and print behavior

scripts/build-www.mjs
  ├─ builds/copies every first-party app into www/
  ├─ builds the How-To SPA into www/how-to-2/
  └─ injects both shared systems into every www/**/*.html file
```

## Guide structure

Original prompts generated by this system use a consistent five-part contract:

```text
ROLE
CONTEXT
TASK
CONSTRAINTS
OUTPUT FORMAT
```

Users can add and persist five reusable context fields:

- exact goal;
- business or user context;
- source inputs;
- constraints;
- required output.

Blank fields remain visible as placeholders rather than being silently invented.

## Interaction model

- **Launcher:** Project Playbooks appears above the App Skill Map launcher.
- **Default scope:** the current app when route detection succeeds; otherwise all apps.
- **Views:** Project Tree, Guide Library and Prompt Builder.
- **Search:** apps, departments, projects, outcomes, guide types, models and capabilities.
- **Filters:** app, model, guide type and saved-only.
- **Progress:** stored in browser `localStorage`; project completion rolls up to the App Skill Map.
- **Shortcut:** `Cmd/Ctrl + Shift + K` toggles Project Playbooks.
- **Accessibility:** semantic dialog, focus trap, visible focus states, labelled controls and reduced-motion support.

## Runtime extension API

A separately built module can add a project:

```js
window.AnchitProjectPlaybooks.registerProject('how-to-engine', {
  id: 'how-to-engine-accessibility-review',
  title: 'Accessibility Review',
  summary: 'Audit the complete tutorial experience for keyboard, contrast and cognitive accessibility.',
  category: 'Learning',
  inputs: 'rendered screens, interaction flows and accessibility requirements',
  deliverable: 'a severity-ranked audit and verified remediation plan'
});
```

A custom guide can be added to any registered project:

```js
window.AnchitProjectPlaybooks.registerGuide({
  id: 'how-to-engine-accessibility-review-screen-reader',
  projectId: 'how-to-engine-accessibility-review',
  title: 'Screen Reader Audit',
  type: 'Audit',
  model: 'Claude',
  description: 'Check semantics, reading order, labels, announcements and keyboard recovery.'
});
```

The public API includes:

- `open()` / `close()`
- `getApps()`
- `getProjects()`
- `getGuides()`
- `getState()`
- `getCurrentApp()`
- `setProjectStatus(id, status)`
- `registerProject(appId, project)`
- `registerGuide(guide)`
- `buildPrompt(guideId, values)`

## Separately deployed apps

Independent repositories can load both shared layers from the portfolio domain:

```html
<link rel="stylesheet" href="https://anchit-tandon.com/assets/app-skill-map.css">
<script defer src="https://anchit-tandon.com/assets/app-skill-map.js"></script>
<link rel="stylesheet" href="https://anchit-tandon.com/assets/project-playbooks.css">
<script defer src="https://anchit-tandon.com/assets/project-playbooks.js"></script>
```

The project runtime includes host detection for the major standalone apps already represented in the App Skill Map. A standalone app can also register additional route-specific projects after these scripts load.

## Security and privacy

- No reference URL or `mcp_token` is committed.
- No prompt-library content is copied from third parties.
- No telemetry is sent.
- Progress, context and saved guides stay in the current browser.
- Clipboard use occurs only after an explicit user action.
- External app links open with `noopener,noreferrer`.
